# ДЗ 3. Работоспособность Boardy: вход через GitHub и уведомления

> **Срок:** 04.11.2026, 14:00 (Екатеринбург) · **Сдача:** Pull request `lab3` → `main`, в описании `Closes #<номер задачи>`

## Цель
Довести до рабочего состояния две функции из ТЗ Boardy, которые сейчас не работают: вход через GitHub и уведомления о новых объявлениях в реальном времени. Результат — обе функции работают с чистого клона, и это показано.

## Перед началом
- ДЗ 2 слито в `main`.
- `git checkout main && git pull` → `git checkout -b lab3`

## Как выполнять
1. **Вход через GitHub.** Заведите своё OAuth-приложение на GitHub и подключите его к Boardy. Ключи — только в `.env`, в репозиторий не коммитить; в `.env.example` — пустые строки с пояснением. *Проверка:* кнопка «Войти через GitHub» → GitHub → вы вошли в Boardy под своим аккаунтом.
2. **Уведомления в реальном времени.** Сценарий: в одном браузере открыта лента, во втором другой пользователь подаёт объявление. В первом браузере без перезагрузки страницы появляется уведомление о новом объявлении — не позже чем через 5 секунд. *Проверка:* сценарий воспроизводится, видео или два скрина приложены.
3. **Найдите, почему не работало.** Пройдите путь события от подачи объявления до экрана получателя и запишите каждое место, где оно терялось, и причину. *Проверка:* в отчёте список «где терялось → почему».
4. **Чините по одному.** Одна причина — один коммит, в сообщении — что было не так. *Проверка:* после каждой правки система поднимается, остальные функции работают как раньше.
5. **Не перегибайте.** Делаем минимально необходимое: брокеры сообщений (RabbitMQ, Kafka), новые сервисы и переписывание существующих в этой работе не нужны. *Проверка:* для каждой правки вы можете сказать, без чего сценарий не работал.
6. **Проверьте с чистого клона:** `git clone` в новую папку → `.env` с ключами → `docker compose up -d` → оба сценария. *Проверка:* оба работают.

## Что сдать
| Что | Где в репозитории |
|---|---|
| Исправления | в коде, по коммиту на причину |
| Список «где терялось → почему → коммит» | `lab/lab3/report.md` |
| Видео или скрины обоих сценариев | `lab/lab3/` |

## Критерии приёмки
| # | Критерий | Баллы |
|---|---|---|
| 1 | Вход через GitHub работает, ключей в репозитории нет | 25 |
| 2 | Уведомление приходит во второй браузер без перезагрузки, не позже 5 секунд | 35 |
| 3 | Причины найдены и записаны | 20 |
| 4 | По коммиту на причину, система поднимается с чистого клона | 20 |
| | **Итого** | **100** |

**Не принимается:** ключи GitHub в репозитории; уведомление только после перезагрузки страницы; все правки одним коммитом; работа сделана нейросетью.

## Как сдать
1. `git add . && git commit -m "…"` по каждой правке → `git push -u origin lab3`
2. На GitHub: **Pull request** `lab3` → `main`, в описании `Closes #<номер задачи>`.
3. Сдано в срок, если запрос открыт до срока — время фиксирует GitHub.

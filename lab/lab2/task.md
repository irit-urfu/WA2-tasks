# ДЗ 2. Исправление архитектуры Boardy

> **Срок:** 14.10.2026, 14:00 (Екатеринбург) · **Сдача:** Pull request `lab2` → `main`, в описании `Closes #<номер задачи>`

## Цель
Поправить реализацию Boardy по базовым принципам — эвристикам (DRY, KISS, YAGNI, SoC, закон Деметры, POLA) и SOLID, — чтобы следующие темы курса строились на ровной основе. Устройство кода меняем, поведение системы — нет.

## Перед началом
- Список нарушений: ваши находки из общего документа «Анализ архитектуры системы» с практики 07.10 и презентация с разбором практики 2, которую выдал преподаватель.
- Система поднимается: `docker compose up -d` → http://localhost:8080.
- `git checkout main && git pull` → `git checkout -b lab2`

## Как выполнять
1. **Зафиксируйте поведение «до».** Пройдите по всем функциям системы (лента, объявление, комментарии, вход и регистрация, подача объявления, API) и сохраните результат: скрипт с запросами и их ответами или тесты. *Проверка:* результат «до» сохранён в `lab/lab2/report.md` или лежит в репозитории.
2. **Составьте план правок.** Из списка нарушений выберите, что исправляете, и у каждого пункта укажите принцип. *Проверка:* в отчёте таблица «нарушение → принцип → что сделаю».
3. **Исправляйте по одному.** Одна правка — один коммит, в сообщении — что было не так и какой принцип нарушен. *Проверка:* после каждой правки система поднимается, функции работают как раньше.
4. **Не перегибайте.** Делаем необходимое: DDD, фабрики «на будущее», новые слои и новая инфраструктура (логирование, метрики, очереди) в этой работе не нужны — сервис маленький. *Проверка:* для каждой новой абстракции вы можете назвать, какую правку она удешевляет.
5. **Проверьте поведение «после».** Повторите прогон из шага 1. *Проверка:* результат совпадает с «до».
6. **Запишите итог.** *Проверка:* в отчёте — что исправлено (ссылки на коммиты), что сознательно не стали делать и почему.

## Критерии приёмки
| # | Критерий | Баллы |
|---|---|---|
| 1 | Система поднимается с чистого клона, функции работают как до правок | 20 |
| 2 | Исправлены нарушения из списка | 40 |
| 3 | Каждое исправление — отдельный коммит с понятным сообщением | 15 |
| 4 | Отчёт: таблица с верно названным принципом, проверка до и после | 15 |
| 5 | Нет перегруза: новые абстракции обоснованы | 10 |
| | **Итого** | **100** |

**Не принимается:** система не поднимается; все правки одним коммитом; поведение системы изменилось; работа сделана нейросетью.
